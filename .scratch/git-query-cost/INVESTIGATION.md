# 工作流测试的 Git 调用开销

> 历史阶段记录：保留当时的诊断与实验结论。正式实现已完成，最新验收见 [RESULT.md](RESULT.md)。

本记录说明一个工作流用例为何出现 330 次 Git 调用，并保留已测量的优化候选。当前仅完成诊断，未修改运行时代码。

基准提交：`8d5e8eae7e458cc19ea3f021129a449699fd7fce`。目标用例为 `ProgressTests.test_launch_is_saved_before_host_and_never_reissued`。原始计数只覆盖测试 worker；追踪其 Python 子进程后，测试本身共有 382 次 Git 调用。runner 启动阶段另有 2 次，不计入下表。

采样使用临时 `sitecustomize` 拦截实际 `subprocess.run`，记录 Git 参数、调用栈和阶段，并继续执行原命令。测试统一通过 `scripts/run_tests.py --test-file tests/runtime/test_workflow_progress.py --match ProgressTests.test_launch_is_saved_before_host_and_never_reissued --jobs 1` 运行。子进程继承采样配置；每个进程分别保存数据，汇总时排除 runner 自身的调用。

## 调用发生在哪些步骤

| 步骤 | Git 调用数 |
| --- | ---: |
| 测试准备 | 154 |
| 初次 start 请求 | 215 |
| advance 请求 | 4 |
| observe 请求 | 4 |
| 重复 observe 请求 | 4 |
| 清理 | 1 |
| 合计 | 382 |

准备阶段真实创建 Git 仓库、写入和冻结需求、创建 worktree，并构造交接输入。初次启动阶段重新解析入口、准备交接、在派发器中验证交接，再在发出启动动作前验证。源码的 `stage_handoff.verify()` 会重新运行 `prepare()`；本用例的主体调用 prepare 三次、verify 两次。四次 worktree 校验还各启动一个 Python CLI，每个 CLI 内有 13 次 Git 调用，合计 52 次。

这是有限的嵌套验证，没有观察到无限循环。多轮验证分别处于控制、派发和发出动作的边界；命令重复不能证明这些边界可以删除。

## 最集中的读取

`entry_prepare.repository_facts()` 在整个用例中调用 37 次，每次读取根目录、共享 Git 目录、分支和 HEAD，贡献 148 次直接 Git 调用。准备阶段和主体均反复经过这个入口。

测试 worker 内还有 197 次相同命令的额外读取，其间未观察到 Git 写操作或 Python 子进程边界。这是保守分类下的候选集合，不是已证明可删除的集合：工作区文件写入、其他进程修改、不同权限校验及恢复边界仍需单独分析。

## 已测量的优化候选

诊断替换仅发生在临时测试 worker 中，没有写入源文件。所有下列模式均通过原用例。

| 候选 | 测试 Git 调用数 | 比基线减少 |
| --- | ---: | ---: |
| 基线 | 382 | 0 |
| 仓库身份读取从四次合并为三次 | 345 | 37 |
| 绑定校验内合并根目录与共享目录读取 | 372 | 10 |
| 主仓库识别内合并根目录与共享目录读取 | 371 | 11 |
| 上述三个读取合并一起使用 | 324 | 58 |
| 同一次冻结源校验复用 ls-tree 结果 | 379 | 3 |

第一批建议只做前三个读取合并：每轮校验仍然重新读取 Git，保留原路径、环境、绑定、分支、提交及失败处理约束。仓库身份读取仍需保留 Git 与非 Git 识别，不能把空仓库或无效 HEAD 的失败当作非 Git 目录。多字段输出还需正确处理路径字符和输出形状。

冻结源的 mode 和 blob 当前会在同一次 source 校验里重复读取树记录。收益只有三次，优先级低；若处理，直接在该次校验内复用读取结果即可。

暂不删除完整交接校验，不引入跨请求缓存、持久快照、跳过验证的标志或测试 fixture 共享。更大的优化应先区分每个边界需要的当前 Git 事实与固定提交对象，并补并发修改和恢复回归。

## 耗时证据与限制

基线与身份读取候选各有三个交错样本。整段用例中位耗时分别为 4.8 秒、4.6 秒；单次耗时有波动。两组带 CPU 计时的样本，worker 自身加其等待的子进程累计 CPU 均值约为 4.20 秒、3.86 秒，约下降 8%。联合候选只有一个样本，用时 4.0 秒。

这些测量包含诊断开销，只覆盖一个健康路径用例，不能外推整套回归速度、功耗或风扇转速。实现前后需验证非法 Git 状态、游离 HEAD、非 Git 目录、路径字符、重定向环境、并发变化和中断恢复；原权限及来源校验必须继续生效。

计数、样本、源文件指纹和运行参数见同目录 `profile-summary.json`。临时诊断脚本仅用于采样，不属于正式测试入口或运行时实现。

采样起点工作区干净；记录完成期间出现其他任务的未提交源码和文档改动，本任务未修改或整合它们。JSON 中的文件指纹在采样后采集，并非各进程导入时的完整快照。正式实现应先固定新的候选版本，再复现这些计数及负面场景。
