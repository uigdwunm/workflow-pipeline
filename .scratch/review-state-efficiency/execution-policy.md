## 开工和划片

在已有方案审阅及每片派发前完成一次预检，使用现有 plan_refs、读写路径、shared_state、依赖和 verification_refs，不增加审批层：

1. 选定可独立验收的完整行为，覆盖产生者、消费者、正常结果、拒绝、暂停恢复及最大合法输入；函数计划用于说明实现，不决定 Agent 数量。
2. 检查后片是否会立即修改前片的同文件、公共边界或共享夹具。强耦合步骤优先合片；不能在上下文预算内合片时串行实施，明确前片证据的失效与累计增量补审点。读写交叠未消除时不宣称可并行或独立保留结论。
3. 给每个 AC/必要失败分支指定首次检查层、verification_ref 和公开验证边界；必须的局部、组合和交付检查分别可定位。首次提交前确定一个快反馈命令及必要组合命令，记录首跑耗时。
4. 核对生产入口、CLI、runner、已支持 ledger/Phase Run 消费者和对应生成映射；只登记与当前行为有关的边界。新写文件须先在 manifest 内取得对应 Ticket 范围，verify 条目保持只读直到实际依赖得到确认。

每组预检一次；先确认合法基线、实际 producer/consumer 与原失败目标，再确定精确写路径和受影响回归。模块数不决定任务数，相同异常不代替因果诊断。未知项留 unknown；verify 项未证明依赖且未获得具体范围授权前保持只读。各组复用原作者/reviewer；独立只读诊断按需并行，共享入口只有一个写入者。

预检缺项返回当前规划者补齐。合同内工程调整由原 Controller 处理；改变文件/步骤/验证合同仍经过已有计划修订，改变公共合同仍交用户决定。一次修复保留原片 ID、实现者和首次提交序号，不为每个补丁建立新片。

## 审查职责

| 层 | 首次负责的事项 | 上层使用已有结果的方式 |
| --- | --- | --- |
| 局部 | 片内行为、失败边界、规范及相关验证 | 保留原 source 和 claim，检查目标适用性 |
| Ticket | 完整 AC、片间顺序、公共输出、共享夹具和依赖组合 | 核验有效局部覆盖，审组合增量 |
| 交付 | 跨 Ticket 合同、共享状态、遗漏文件、全部需求覆盖 | 核验有效 Ticket/局部证据，审跨 Ticket 增量 |

同一事项再次检查须记录触发原因及影响范围：指纹/依赖/合同变化、未解决 finding、证据缺失或未知影响。上层覆盖核对不等于重新逐行审查全部代码。单片 Ticket 可由同一独立 reviewer 连续完成局部与 Ticket 验收并复用读取上下文；仍按各自 scope、原生动作、停止回执和依赖生成明确结论，不把局部报告重标为 Ticket 报告。

每片停稳、回归通过后局部审查；findings 回原执行者修复，同 reviewer 复查增量。全部片有效后验收 Ticket；全部 Ticket 有效后完成两轴交付审查及当前候选完整验证。每片不是必须有独立 Git commit；只读审查可用稳定不可变快照。正常轮询、无新代码/证据变化不派新 reviewer 或重做报告。

## 验证分层

快反馈测试使用真实模块的公开边界，检查一个行为及其必要反例；仅构造该边界需要的有效输入。权限、存储、Git/CAS 和停止证据由对应真实模块验证，不用假的 pass/权限消费者替代。边界要求磁盘或 Git 时使用真实临时资源。

组合测试经真实 `workflow_progress.handle`、CLI、runner 或已支持 ledger/Phase Run 路线，证明接线、权威与原调用恢复一致；宿主响应可用确定性 adapter fixture，并标明不是原生现场。每片只跑相关回归；共享接口/夹具或两片整合时立即跑 affected/Ticket 检查，首次提审前完成。共同输入/读取入口及已知失败收敛后固定最终候选再跑完整验证；完整 gate 失败后的源码修复须重新绑定最终候选完成全量，不能以局部通过替代。

规模数据由真实存储提交/引用接口构造合规历史，另以少量公开流程用例核验接线；不为每个历史项重跑整条阶段链，也不直接写 JSON 伪造已提交权限。修订合同内的必要故障/批次边界仍须覆盖，不追加已延期的万级/物理配额基准。源输入变化才重做相应生成包核验，源码和 canonical 输出在同一候选保持一致。

所有仓库测试只经 `scripts/run_tests.py`，最终经 `scripts/validate.sh`；沿用最多两个 worker、nice 10，不在本轮修改 runner。首跑结果及命令选择决定后续回归集；修复测试准备时只复跑失败项及实际受影响检查，已有适用证据明确复用。测试快不以删失败分支或放宽校验换取。

## 返工触发短诊断

| 已确认触发条件 | 下一步 |
| --- | --- |
| 同片连续两次因测试准备/断言错误失败 | 先验证测试输入与结果渠道，收敛合法基线和命令选择，再继续实现 |
| 同一公共边界两轮审查修复后仍新增该边界缺陷 | 重新检查产生者—消费者合同、完整拒绝路径及验证边界，再做一次连贯修复 |
| 已接受片因后片同文件/共享边界变化失效两次 | 回看划片，合并紧密步骤或确定串行累计增量补审点 |

记录触发事实、问题分类、受影响片和处理结论，复用当前片/事务。分类依据真实结果；未知原因保留 unknown，计划内 TDD RED 单列，不自动记为模型首次提交失败。短诊断不撤销有效成果、不放行 finding、不自动取消/暂停整个任务；公共合同或权限范围变化仍走原门禁。完成条件是触发原因已有可验证处理，必跑检查和权限仍完整。

## 当前记录与读取预算

一个管理记录是当前入口，保存目标版本、Ticket 进度、阻塞、活动调用/runner、下一步和证据引用，canonical UTF-8 ≤16 KiB。它只协调任务，不替代运行时原控制权威、lease 或停止证明。到达上限先移出已完成历史及重复投影；必要当前事实仍超限则阻止新派发并诊断，不运行中增容。历史验收、原输出及完整快照按引用取；连续性文档只解释入口和历史索引，不另写一份当前状态。

片/命令/审查状态转换时替换当前字段，关闭后的旧下一步移出当前入口。原调用仍未知时保留其身份与恢复事实。相同 poll 只聚合计数/最近观察，不生成新的报告或完整快照；仅证明对象没有变化的观察不改变权限。阶段/Ticket 完成后历史退出活跃读取；运行时归档按 PRD 的原权限/引用规则；本轮不自动删除原证据或临时历史，年龄/两代扫描 GC 延期。

默认模型输入包的管理状态、摘要和必要合同合计 ≤64 KiB UTF-8；一次按需展开的合计 ≤256 KiB，原文按 ≤64 KiB 分段。交接/恢复报告实际总读取字节及文件数，包含展开的依赖/证据，区分模型输入与结构化权限核验读取；引用化不豁免读取计量。现有 root/subject、2.25 MiB 日常元数据和原证据读取预算仍须满足，最终分页交付审计另计。
