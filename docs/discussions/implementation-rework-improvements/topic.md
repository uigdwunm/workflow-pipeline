# implementation-rework-improvements

## Goal

评估实现返工复盘建议的必要性，选择能减少无效返工且不增加普遍流程负担的最小改进范围。

## Background and Current State

- 用户已确认三项候选范围及第一、第二项最小方案。第三项具体机制待确认，仍未授权修改 Skill 或进入实现。

## Scope

- 关键合同一致性：已确认补强现有方案就绪检查，对本次改变的接口、状态或调用时序，核对相关既有规格及真实调用链，发现矛盾先解决再交付。
- 真实链路验证：已确认在现有 TDD 纵向切片中，先以代表性行为验证本次改变的关键真实内部边界，再扩展同类实现，不用替身绕过正在验证的边界。
- 同根因返工处理：在已确认候选范围内继续讨论具体触发条件与处理动作。

## Non-goals

- 不修改 omni-memo 业务代码，本轮不立即修改 Skill。
- 不新增工作流阶段，不增加普遍门禁或固定审查轮次阈值，暂缓增量审查机制。
- 提前整合检查和状态措辞不作为本轮必须修改项。

## Users and Key Scenarios

- 涉及跨端或持久化状态重构时，核对受影响的既有接口、时序与恢复约束。
- 测试应真实经过本次最易失配的模块边界。
- 同一根因在连续审查中反复出现或方案被推翻时，重新诊断而非机械续接补丁。
