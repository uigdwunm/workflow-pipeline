# 1拷问草案：总控对话与五阶段调度流程

## 目标与预期结果

重新规定五阶段工作流何时创建用户可见的专用任务、何时使用原生子 Agent，建立稳定的话题总控，让用户决策、上下文交接、执行和验收有明确归属。新任务必须先准备后确认，用户要求在当前任务执行时遵从。减少重复确认、上下文丢失和重复执行，并按任务难度与成本选择模型及推理强度。

本次1拷问已完成，用户已确认交付及由原任务以连续模式执行后续流程。本草案描述拟改造流程，不代表已实现；原任务继续作为总控。

## 背景与现状

当前0讨论具有持久话题、检查点、绑定、子话题和0/1依赖门禁；1拷问按上下文质量选择是否迁移，具备独立任务交付和原任务接收协议；2方案已由主任务调度隔离上下文的方案子 Agent；3实现由来源任务监督专用实现任务；4归档负责最终发布与清理。

现行讨论生命周期允许0→1、0→2、1→2、2→3、3→4，不支持附着话题0→3。连续模式入口的文字规则分散，0来源明确禁止传播连续模式。ADR-0005允许显式、无讨论绑定的独立实现入口。一个 Flow Worktree 从方案或独立实现贯穿到归档。需求文档与正式方案有不同权威。

## 范围

### 包含

- 五阶段入口、总控身份继承、专用任务与原生子 Agent 的角色边界。
- 创建前的上下文整理、唯一需求草案、组合确认、用户拒绝新任务的处理。
- 0/1子话题拆分、子话题总控、建议顺序和强依赖说明，沿用现有门禁语义。
- 专用任务结果回传、总控接收、下一阶段启动与旧任务归档。
- 0→2连续模式及可能直接实现的入口资格。
- 3实现的单一调度者与执行层、按需并行执行模块、边界协调和整体集成责任。
- 4归档委托及整体完成验收；模型和推理强度动态选择。
- 上述行为必要的错误、重试、取消、恢复及可验证验收条件。

### 不包含

- 本次拷问期间修改 Skill、实现脚本、测试或安装配置。
- 为所有辅助 Skill 自动创建任务，或重建无关领域流程。
- 自动取得远程发布、破坏性操作或额外付费的权限。
- 此时确定文件拆分、内部字段或具体技术实现。

## 用户与关键场景

1. 用户在最初任务进入0讨论：提炼讨论点及相关上下文写入唯一草案，说明当前为总控，准备好专用讨论任务后确认创建；拒绝则在当前任务继续；普通拒绝仅当前阶段有效，明确的话题级偏好持续到本话题后续阶段。
2. 初始目标或0/1过程中适合拆题：按已有拆题条件提出独立目标、边界、关联、顺序和强依赖；拆题创建只产生一个子话题总控，不同时创建专用讨论任务；该总控继承已整理的材料，后续专用讨论按阶段入口规则处理。
3. 专用0完成：向总控回传，总控接收并梳理结论，选择1、2或满足资格的3；确认中包含下一步与归档旧讨论任务。
4. 独立进入1或0→1：准备唯一草案后确认专用拷问任务；阶段进入与任务创建合并确认，避免重复询问。已有总控身份必须继承，专用任务不能再次递归创建同阶段任务。
5. 2方案由总控调度方案子 Agent，不额外创建用户可见的方案任务；0→2可在明确披露后确认连续执行后续流程；0→3保留为简单改动的独立实现入口，但须满足明确资格。
6. 3实现由总控派发一个实现调度子 Agent，调度者按文件边界决定是否并行派发执行 Agent；总控协调超出既定边界的调整。
7. 4归档由总控派发归档子 Agent；实现问题返回3，整体结果仍由总控核验。
8. 创建失败、回传重复、归档失败、调度者中断、依赖重新关闭或执行边界变化时，不重复已经成功的动作，也不擅自扩大授权。

## 约束

- 本目标只有一个需求文档；创建专用任务后转交写权限，总控不并发改写。
- 留在当前任务的偏好按 D1 的阶段级或话题级范围执行，不自动跨话题继承。
- 用户确认绑定具体待执行动作、目标和证据；能合并的阶段/创建/归档动作一次披露确认。
- 不把已接受方案范围内的技术协调升级成反复询问，也不把连续模式作为扩大范围的授权。
- Topic Dependency只管0/1需求门禁，不替代实现任务依赖调度。
- 多Agent共享工作区须按 D7 避免并发Git索引、提交、分支和清理冲突。
- 专用用户任务与原生子Agent不能混同；两种载体必须按运行时实际能力使用。
- 模型选择不得写死单一型号；用户指定优先，选择支持的模型/强度组合，执行不一律视为简单工作。

## 决策与理由

当前权威参见ADR-0001（讨论状态与工作区执行分离）、ADR-0005（显式独立实现）、ADR-0006（0/1话题依赖门禁）。本次尚未新增或修改ADR。

已接受的设计方向：一话题一总控、0/1专用任务、2保留方案子Agent、3调度/执行分工、4委托且总控验收、模型按角色与难度选择。具体新行为应先在本草案定案，再由2方案处理与现有协议冲突。

### D1：留在当前任务的偏好范围（已确认）

普通“就在这里做，不开新对话”只约束当前阶段；明确“这个话题后面都在这里”覆盖本话题后续阶段，不再反复建议创建专用任务。偏好不自动继承给子话题或无关独立调用，只限制用户可见新任务，不限制按阶段规则调度的原生子 Agent。用户在本专用任务对 Q1 回复“可以”，确认该边界。

### D2：拆题创建的任务数量（已确认）

用户回复“只创建总控”：拆题创建只产生一个子话题总控，不允许同一次拆题创建同时产生总控和专用讨论两个任务。总控继承已整理的材料；后续是否创建专用讨论任务按阶段入口及偏好规则处理。依赖门禁关闭时的行为见已确认的 D3。

### D3：依赖关闭时的子话题边界（已确认）

用户回复“可以”：依赖未满足时，子话题总控可接收材料、查看依赖与恢复状态并说明等待条件；不得创建专用讨论任务、开展实质讨论或推进阶段。只有用户再次请求且门禁满足后才继续；不自动轮询或后台启动。

### D4：0→3 独立实现入口（已确认）

用户要求“保留吧，总有一些简单的改动”：保留 0→3，但仅作为简单改动的独立 Stage 3 入口。必须有明确目标、已有充分实现依据、可验证的低复杂度范围，并确认不需要需求拷问或方案产物；否则仍走 0→1→2→3。该入口无讨论绑定，不改变总控对用户决策、实现结果和后续归档的责任，也不能绕过真实阻塞或扩大授权。

### D5：连续模式的覆盖范围（已确认）

用户回复“可以”：0→2 的连续确认仅覆盖确认块中已明确披露的 2方案、必要的 3实现、4归档及标准交接。遇到用户决策、权限扩展、阻塞、异常或范围变化立即暂停并回到总控；连续模式不传给子话题或独立调用。

### D6：回传、接管与归档顺序（已确认）

用户回复“确认”：总控先验证专用任务回传的来源、版本、提交和哈希，再接收并记录结果；若继续下一阶段，先完成阶段入口和交接验证，确认新阶段已成功接管后再归档旧任务。任一步失败都保留旧任务和恢复状态，不重复已成功动作。

### D7：3 阶段调度与 Git 集成（已确认）

用户回复“确认”：总控只派发一个实现调度子 Agent；调度者按模块边界决定是否并行派执行 Agent。执行 Agent 只能写明确分配的文件范围，共享文件由调度者串行协调。调度者负责统一集成、测试和候选提交，总控负责整体验收与阶段交接；多个 Agent 不得直接争用同一 Git 索引或提交。

### D8：调度者故障与容量恢复（已确认）

用户回复“可以”：总控先读取调度者最后检查点，确认已完成的执行、文件范围和候选状态；只对未完成部分替换调度者或降级串行执行。替换者不得重复已验收动作，必须重新验证未完成结果；若无法保持原边界则暂停并请求用户决定，不静默改变范围或授权。

### D10：旧交接兼容范围（已确认）

用户澄清“没有旧交接，我现在是在做这套 skill”：当前不存在需要兼容的旧交接、进行中话题或历史绑定。本次规则作为新 Skill 的初始行为契约，不需要迁移、重绑或兼容分支。

### D9：模型与推理强度选择（已确认）

用户回复“可以”：创建用户可见专用任务或启动重要子 Agent 前，披露角色、模型、推理强度和选择理由；普通执行 Agent 只记录配置，不逐个打扰用户。所有选择先校验当前能力；不可用时只升级到受支持组合并记录原因，不无限重试。若升级改变成本、权限或用户可见任务身份，则暂停并请求确认。

## 必要的方向变更摘要

“每个Skill都开新任务”收敛为五阶段按角色选择载体；内部辅助Skill和已授权专用任务入口不得递归创建任务。

## 验收条件

以下为依据已确认决策整理的验收条件，不是已实现结果。

- 明确准备和创建两个时点；创建确认前无新任务；用户指定当前任务后在同一草案继续。
- 普通拒绝后，本阶段不再建议新建专用任务；明确话题级拒绝后，后续阶段也不再建议；子话题和无关独立调用仍按各自偏好处理，原生子 Agent 不受该偏好限制。
- 总控身份跨阶段不漂移，专用任务不会再次为同阶段创建任务；子话题保留父级关联和独立总控。
- 组合确认只执行披露的动作，拒绝或修改不被误读为无条件同意；0→2连续模式仅覆盖已披露的标准阶段和交接，遇到阻塞、异常、授权扩展或范围变化立即暂停。
- 回传有确切来源和文档版本；总控先验收并记录，再验证下一阶段接管，最后归档旧任务；失败保留旧任务和恢复状态，重试不重复已成功动作。
- 一次拆题创建只产生一个子话题总控，不连带创建专用讨论任务；依赖未满足时总控仅做接收、检查和恢复说明。
- 拆题的推荐顺序与强依赖区分明确，现有门禁在0/1继续生效。
- 0→3 仅在简单改动且已有充分实现依据时作为无讨论绑定入口；不满足资格时不得绕过需求与方案阶段。
- 3阶段由单一调度者统一协调、集成、测试和候选提交；执行 Agent 按明确文件边界工作，共享文件串行处理，总控验收和交接。
- 方案、调度、执行和归档职责清晰；并行模块不越界、不争用Git写操作；统一集成后才报告实现完成。
- 调度者不可用时可根据已记录事实恢复，不丢失已完成交付，不重复已成功工作。
- 新任务/重要 Agent 披露模型与强度；普通执行记录即可。能力不可用时有限升级，改变成本、权限或可见身份则重新确认。
- 文档、脚本入口校验、用户提示与恢复分支的行为一致，并覆盖以上正常与异常场景。

## 未决问题与延期项

本次不新增后台监控或调度服务；普通回传、重复交付与失败重试沿用现有专用任务交付协议，阶段接管及归档顺序采用 D6。用户要求将更广泛的接续机制改造放到独立对话，不作为本主线的依赖；该独立工作已合入的实现作为仓库基线，不重新设计或复制。
