# 工作流 Skill 独立安装需求

来源：当前任务已确认的用户对话。
状态：已确认，供 2方案使用；本轮只授权方案和本地规划产物，不授权实现、部署、远程发布或进入 3/4。

## 目标

开发时共用规则和代码保持单一维护来源，发布安装时五个工作流 Skill 各自包含完成自身职责所需的内部文档和运行脚本。用户只安装任意一个工作流 Skill，在其必要 Matt Skill 与基础运行环境齐备时，应能完整运行本阶段，不要求安装其余四个工作流 Skill。

## 已确认边界

1. 范围为 design-discussion、problem-framing、solution-design、guided-implementation、change-closure。
2. 共用源码允许复用，发布副本由构建过程生成，不手工分别维护。
3. 消除本阶段执行所需的跨工作流 Skill 安装目录读取、导入、脚本定位与隐式存在假设。
4. 保留全部现有阶段职责、文档权限、验收、Git/worktree 和讨论状态权威，不因物理打包而分裂状态或绕过验证。
5. 明确保留 3实现现有能力，不扩充：实现、测试、审查、候选提交及保留 worktree；合并、文档归档和清理由 4归档负责。
6. 不内置、改造或替代 Matt 系列 Skill。默认用户已安装所需 Matt Skill，缺少必要依赖时明确报错提醒，不静默替代或自动安装。
7. 连续执行所需后续阶段不全时提醒；不自动安装，不冒充完成，不代做缺失阶段。方案需具体定义预检时点、提醒和保留/恢复语义，不引入新的业务职责。
8. 单独运行本阶段不因未安装未使用的后续阶段而失败；跨阶段交接仍验证实际目标及所需协议兼容性。
9. 保留现有基础环境要求；不扩展为 Windows 支持、无原生子 Agent 环境适配或独立新平台支持。

## 已核实的当前问题

- 共用需求文档、确认、拆题和生命周期规则放在 design-discussion；其余阶段按跨目录路径引用。
- thread_settings、workflow_control、supervision 等共享运行能力放在 guided-implementation；discussion_core/workflow_control.py 直接导入该兄弟 Skill 的脚本。
- workflow.py 使用相邻目录定位阶段 2/3/4；现有安装说明要求五个 Skill 同版安装。
- 当前校验主要检查源码布局和约定安装根，未证明单个发布包脱离源码和其他四个 Skill 后可用。
- omni-memo 新任务故障中，项目缺少 design-discussion 链接；Matt 依赖实际存在但搜索误判。此次方案解决内部安装耦合，外部依赖检查应避免同类链接漏检。

## 验收条件

- AC1：五个发布包均只有自己的用户入口，完成自身职责所需内部资源均位于本包内；必要外部 Matt 依赖明确可查。
- AC2：共用源修改能确定性传播到依赖它的发布包；构建检查阻止手工发布副本漂移、越界链接、缺漏资源与错误导入。
- AC3：每个包在无源码仓库、无其他四个工作流 Skill 的隔离安装环境中，内部脚本及阶段关键路径可验证；不以静态存在检查冒充完整 Agent 行为验收。
- AC4：必要 Matt 依赖缺失时可定位报错；存在且通过合法符号链接安装的依赖不会因不跟随链接被误报；不修改 Matt 本身。
- AC5：单阶段成功不依赖下一阶段安装；连续阶段缺失、不可读、不兼容或执行途中消失有明确提醒和恢复语义，不重复已完成工作。
- AC6：组合安装下仍保留有效交接、唯一需求文档、单一讨论状态和同一 Flow Worktree；3/4 职责不变。
- AC7：发布安装流程、依赖说明、更新与版本兼容策略、测试入口与发布产物一致；不用本机私有安装状态证明普遍可用。

## 非目标

内置 Matt、修改 Matt 工作流、自动安装其他 Skill、扩大阶段职责、修改业务项目、在本轮部署或实现、创建另一套讨论或执行状态中心、把第三方工具能力误称为安装包自身能力。
