## 方案阶段必须解决的问题

1. 用有界、隔离、可清理的验证核实实际宿主对原生角色存活、寻址和续接的支持。保留原生回执，区分真实验证与模拟证据；验证受限时报告缺失能力，不能用假定补齐结论。
2. 区分原角色仍运行时的等待、角色本轮结束后的下一次工作，以及外层进程退出后的恢复；为每类情况确定责任方、允许动作和证据。
3. 决定如何在退出发生前保护执行环境，以及退出发生后如何检测和恢复。仅在进程退出后拒绝 continue 不足以证明问题已被预防。
4. 明确正常进度、用户决策、暂停、取消、进程崩溃、回执丢失、宿主不支持查询及子 Agent 不可见时的行为与优先级。
5. 将修复放入现有 runner/C/宿主适配接口，保持唯一状态权威；明确协议与生成包变更、旧版本使用边界和验收入口。

## 可观察验收条件

- 活跃原生角色的正常等待不依靠结束并重启其所属执行环境；进度输出不会被解释成最终交出控制权。
- 正常续接保留同一可信身份和工作范围；宿主事实不足时不能新建角色冒充续接或宣称整体完成。
- 外层退出、崩溃或回执保存中断后，既有代码/文档与调用记录保留，不重复派发、重放未对账写入或重复发布。
- 暂停和取消遵守原写入者停止核验；有嵌套执行角色或审查角色时也能正确收尾，不能只检查一个根角色。
- 回归测试驱动真实 runner/C 调用接口；真实宿主验收另行证明角色存活与续接，不能用仅包含固定字符串的模拟回执充当证据。
- Spec 给出真实调用链、状态分支、失败恢复、兼容策略及与以上验收逐项对应的测试安排，使阶段 3 不再承担实质架构决策。
