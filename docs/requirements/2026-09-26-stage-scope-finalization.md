# 阶段范围定稿与交接恢复

Status: frozen
Source: 本对话已确认的修复目标，2026-09-26。

## 问题
删除记录案例的 Stage 2 已 accepted 且 downstream_ready=true，implementation_paths 和 closure_paths 却为空。prepare 允许空数组，方案验收只验证规划成果，下一阶段只能缩小实现范围、保持归档范围，导致空范围或漏文件无法推进。

## 已确认目标
1. 区分后续范围未确定与明确为空。Stage 2 启动冻结需求、规划写入范围、目标、Flow Worktree；设计完成后由设计者给出精确实现/归档文件清单及 Spec/Ticket 依据，Controller 核对后冻结正式交接。
2. 区分规划完成与实现交接就绪。需要实现的方案不能用空实现清单返回 downstream_ready。归档清单可以明确为空。覆盖测试、新文件、生成文件及必要文档，检查保护路径与所有权冲突。发布前检查、Stage 3 入口重验，错误报告缺项和恢复动作。
3. 提供受控范围修订，覆盖空清单和非空漏文件。绑定原需求、规划提交、工作区、原清单、差异和 Controller 决策。未启动实现时可补齐后继续；已有执行者时先停止相关写入并处理未决调用。需求或业务方案变化仍走原变更决策，不覆盖历史或重算摘要伪造原授权。
4. 为旧协议中 Stage 2 已验收、Stage 3 未启动记录设计窄恢复路径。保留旧记录、规划提交和同一工作区，以补充范围授权建立可追溯的新交接。固定包身份不能偷偷替换，兼容例外必须写入 ADR。不迁移已进入实现的旧运行。
5. 需求范围内文件细化不新增用户审批；功能、权限、副作用实质扩大仍需用户决策。不得用全仓授权、目录通配或放松保护规避问题。

## 本次交付和边界
仅冻结需求、Spec、必要 ADR 和 Tickets。审阅通过后合入本地 main 的规划载体，保留 Flow Worktree。本次不实现、不安装、不部署、不创建 PR、不推送、不修改删除记录原对话或真实运行记录。模型切换报错另案处理。

## 约束
保留 Controller、设计者、Dispatcher、归档角色边界及单 Flow Worktree。复用已有 checkpoint 与控制权威，不另建并行 ledger。设计覆盖 interactive、foreground runner、独立及附着讨论入口。冻结需求只读，历史接受记录及宿主证据不可伪造，升级不自动影响旧运行，保留无关工作。

## 可观察验收
- 未定范围、需要实现却为空、漏掉已批准变更路径均不能误报就绪。
- 完整清单正常交接，明确无需归档修改允许空清单。
- 越权路径、保护冲突、陈旧决策/证据、源或目标漂移均拒绝且不派发。
- 修订中断可恢复，重复请求不重复派发/发布/接受，历史不被覆盖。
- 用删除记录同结构的旧记录验证窄恢复，保留已有成果，不重复设计或发布，不使用真实业务记录写入测试。
- 正常路径、独立阶段、连续模式、工作区复用、归档保护保持。

## 方案阶段工程问题
确定 scope 表达、生命周期、所有者和封存时点，修订因果与停止屏障，协议和兼容键，旧记录只读验证及新交接授权/消耗，附着讨论和 runner 约束。主要测试 seam 使用真实 Git 和协议入口，宿主替身仅模拟可认证响应，不把静态摘要或布尔字段视作授权。列出精确实现/测试/生成/文档路径，避免本方案再产生空范围交接。
