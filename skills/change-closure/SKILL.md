本 Skill 使用本任务唯一的临时进度文件组织归档，不另建执行清单。各大步骤的具体操作与完成条件以[执行说明](references/execution.md)为准。

首次进入本阶段时取得包含时区的 ISO 8601 开始时间，写入进度文件；接续时沿用本轮开始时间。

# 输入

从已有交接、进度文件和实际成果中取得：

- 原目标项目的绝对路径，以及本次任务的整体目标与最终确认范围。结合初始任务简介和后续用户明确确认的内容整理；独立进入归档时，从需求或交接成果中取得，不能用“归档代码”代替任务目的。初始简介保留在进度文件中，“本轮仅讨论”等阶段性限制作为历史记录，报告描述整个任务。
- 用户常用工作区的绝对路径及已有检出状态记录，结合当前实际状态核对。没有单独指定时，常用工作区为原目标项目目录，与集成 Worktree 分别确认。
- 同一进度文件的绝对路径、任务标识和原目标项目；首次进入体系时创建一次。
- 集成 Worktree 的绝对路径、集成分支和目标分支。目标分支默认 `main`；用户明确指定其他分支时使用指定值。
- 待归档实现提交。
- 本次已有结果产物的名称及实际路径或链接。

信息明确时直接使用；只针对无法从上下文或实际成果确定的缺项向用户询问。目标项目和本次任务明确后，先创建或复用进度文件；归档输入尚不齐全时，保留阶段开始时间，补齐后再登记输入和推进。

# 本地文本写入

遵守目标项目的文件写入约定，优先使用宿主文件编辑工具。使用 Python 写入文本时，在源码前两行声明 `# coding: utf-8`，文件读写显式指定 `encoding="utf-8"`。长文正文使用多行文本或独立数据输入，避免嵌成超长单行源码。交给其他执行者时传递本节要求。

# 任务进度与归档输入

使用本 Skill 的[进度脚本](scripts/task-progress.py)，由主对话统一维护进度文件。只在大步骤完成时记录序号、一句结果和完成时间，不为确认、等待、冲突或整改另建记录。

首次进入体系时，遵守项目写入约定，选择用户指定或项目约定的位置；没有约定时，使用宿主现有临时目录中的唯一文件路径。文件位于临时 Worktree 之外，父目录须已存在：

```sh
python3 '/Skill绝对路径/scripts/task-progress.py' create \
  --output '/本任务进度文件绝对路径' \
  --project '/原目标项目绝对路径' \
  --summary '本任务原始要解决的问题和目标' \
  --stage 4 --at '进入本阶段时取得的含时区ISO时间'
```

保存返回的 `file`、`task_id`、`project` 和本轮 `started_at`。已有交接时，用 `show` 核对同一文件的归属和实际成果，再用 `enter --stage 4` 进入或复用本阶段；首次追加时用 `--at` 传入实际开始时间。后续命令均传入同一组 `--file`、`--task-id` 和 `--project`。文件缺失、损坏或归属不明时，先核实，不能另建文件替代。

输入齐全后，将以下 JSON 的示例值换成实际信息，作为 `--closure` 传给首次 `create` 或 `enter --stage 4`，与开始时间一起存入同一文件；已创建阶段时，用同一次 `enter` 补齐输入：

```json
{
  "worktree": "/集成Worktree绝对路径",
  "branch": "codex/example",
  "target_branch": "main",
  "implementation_commit": "6f3a8b1",
  "artifacts": [
    {"name": "Spec", "location": "/实际成果绝对路径/spec.md"}
  ]
}
```

归档输入必须在第一个大步骤完成前保存。本轮输入作为接收基准，不随整合、交付或工作区清理改写；后续提交、成果位置和资源结果记录在对应大步骤的一句结果中。接续时读取原记录，不重复登记输入。确实重新执行已结束归档时，用 `enter --stage 4 --new-run --closure ...` 追加一轮，保留旧记录。

已有旧归档清单时，先核对归属、实际成果和仍有效的完成依据，作为接续资料使用，不继续维护第二份进度。旧前四步按职责核对；旧六步中的清理和报告合为当前第五步。历史完成时间没有可靠记录时不补造时间，本次核对通过时记录当前时间，并在简要结果中注明沿用旧成果。属于本任务的旧临时清单，在迁移核对成功后按项目清理授权处理；需交付或明确保留的文档遵守原约定。

# 执行流程

## 用户工作区

常用工作区的检出分支和编辑器项目位置由用户控制。除用户明确要求外，归档不替用户切分支、进入 detached 状态或将用户的编辑器项目切到任务 Worktree；用户自行切到其他分支时保持其选择。按[执行说明](references/execution.md#2-检查目标分支变化并完成文档)确定本地交付位置并核实常用工作区的实际结果。

## 待用户决定的事项

从当前对话、交接及执行记录中核对影响本任务范围、实现、验收或交付的待答问题。得到用户明确答复前保持未决；已有范围限制约束可执行的改动，不代替用户对新范围问题的回答。用户已明确决定延期或排除某项且剩余范围可独立验收时，按调整后的范围收尾，并在报告中说明决定及依据。

等待期间继续不依赖该决定的工作，没有可继续的独立工作时等待。阶段和整个任务保持未完成，保留接续所需资源及同一进度文件；问题已提出后，等待本身不触发报告、进度更新或阶段结束。连续模式、已完成部分的测试或交付结果均不能代替这一完成条件。用户答复后核对已有成果，沿用当前轮次接续。

## 按大步骤执行

按下表顺序执行，只读取当前大步骤需要的执行说明；已读取且未变化的内容可以复用。

| 序号 | 大步骤 | 执行说明 |
| --- | --- | --- |
| 1 | 接收成果 | [第 1 节：接收成果与核对归档前提](references/execution.md#1-接收成果与核对归档前提) |
| 2 | 分支检查与文档收尾 | [第 2 节：检查目标分支变化并完成文档](references/execution.md#2-检查目标分支变化并完成文档) |
| 3 | 合并交付 | [第 3 节：整合、验证并合并交付](references/execution.md#3-整合验证并合并交付) |
| 4 | 更新项目状态 | [第 4 节：更新项目状态](references/execution.md#4-更新项目状态) |
| 5 | 清理与报告 | [第 5 节：清理资源并报告](references/execution.md#5-清理资源并报告) |

涉及远程 Git、PR、Issue 等外部操作时，核对操作对象、范围和已有授权。已有授权覆盖本次操作时直接执行；缺少授权时，说明具体操作及影响，取得用户同意后执行。

前四步各自达到完成条件后调用一次 `complete`，填写对应序号和一句结果：

```sh
python3 '/Skill绝对路径/scripts/task-progress.py' complete \
  --file '/本任务进度文件绝对路径' \
  --task-id '创建时返回的任务标识' \
  --project '/原目标项目绝对路径' \
  --stage 4 --step 1 --note '成果、来源提交及已有验证和审查已核实'
```

简要结果包含后续核对和最终报告需要的依据：

- 第 1 步：成果范围、实现提交及已有验证、审查结论。
- 第 2 步：交付方式、仓库与目标、合并策略、目标提交及文档收尾结果；本地交付包含常用工作区路径及检出分支。
- 第 3 步：本地或远程交付、实际交付提交、适用的 PR 链接，以及最终验证、审查结论和必要的未验证范围；本地交付包含常用工作区的实际分支、HEAD 及相关文件是否显示本次成果。
- 第 4 步：状态更新及其交付结果、相关记录位置；无需操作时说明依据。

不适用的操作经核实后，在对应大步骤结果中写明“跳过”及原因。大步骤的处理仍记为完成，不把跳过操作说成实际执行。

第五步先按执行说明处理资源，再按下节生成报告，由报告脚本一次记录第五步和阶段结束时间。原已完成且依据仍有效的记录直接复用；必要返工在当前未完成大步骤的最终结果中简述。

普通等待或中断不更新文件。恢复时用 `show` 核对同一记录和实际成果，只继续未完成的大步骤，沿用本轮开始时间。结果不明确时先核实原操作，核实前暂停重复执行。进度或执行说明缺失时保留已有资料，暂停受影响工作并说明缺口。

# 固定结果报告与结束

资源处理完成、前四步均已记录，且按[待用户决定的事项](#待用户决定的事项)核对后没有未完成或待决事项时，调用[结果报告脚本](scripts/render-result.py)：

```sh
python3 '/Skill绝对路径/scripts/render-result.py' \
  --file '/本任务进度文件绝对路径' \
  --task-id '创建时返回的任务标识' \
  --project '/原目标项目绝对路径' \
  --summary '整个任务的目标与最终确认范围' \
  --artifacts '[{"name":"目标项目","location":"/原目标项目绝对路径"}]' \
  --resources '临时分支已清理；集成 Worktree 按来源保留，已记录原因' \
  --pending '无' \
  --complete
```

`--summary` 填按[输入](#输入)核实的整体任务描述，使用非空单行文本；完成、受阻和取消报告均须提供。完成情况由实际步骤和未完成事项表达。`--artifacts` 填本次归档后的实际交付位置，包括适用的成果文件、项目或 PR 链接；工作区已清理时使用交付后的真实位置，不继续引用已删除的临时路径。没有额外位置时允许 `[]`。`--resources` 如实概括已清理、保留及不由本 Skill 管理的资源，包含必要原因。

所有报告均须显式传入 `--pending`。填写实际未完成和待决事项；只有核对后确认均已解决，或用户已明确延期、排除且剩余范围验收通过时，才填 `无`。脚本校验传入值，待答问题及其解决依据由主对话核实。

脚本使用 `--summary` 作为报告的“本次任务”，从进度文件读取归档输入和前四步结果，生成固定 Markdown 报告，并在同一次调用中记录资源处理结果、第五步完成时间和阶段结束时间。初始任务简介保持不变。只显示实际进入过的阶段；各阶段用时按起止时间累计，包含阶段内等待，不包含阶段间等待。

脚本成功后，先保存完整标准输出。归档完成且整个任务已结束、报告内容已保留后，按项目清理授权调用 `cleanup --task-finished` 删除这一份临时进度文件；不将其作为长期交付文档。还有后续工作或任务结束尚不明确时保留文件。完成适用的进度清理后，以保存的完整输出作为最终回复正文原样展示。

执行异常导致归档受阻、需要报告实际结果时，用同一报告脚本省略 `--complete`，传入实际 `--pending '未完成事项、已知结果及接续条件'`，可用 `--resources` 说明已有资源处理结果。脚本输出未完成报告，不结束阶段、不删除文件。普通等待用户答复按[待用户决定的事项](#待用户决定的事项)处理，不调用报告脚本。用户明确取消归档或整个任务时，先用 `stop --stage 4 --note '具体原因'` 结束本轮，保留已完成步骤；保留实际结果报告后，仅在整个任务已结束时清理文件。

生成报告或进度写入失败时，保留原文件和已有输出，核对实际状态，仅补齐剩余操作。成功报告的重试须沿用已记录的资源结果，保留首次结束时间，不重复清理或交付操作。

# 结果与完成条件

适用的交付、文档、验证、审查、状态更新和资源处理均已完成，不适用操作已有依据，且没有影响本次归档的未解决事项时，才能生成已完成报告。

完成判断以实际产物、Git 状态、必要的外部状态和同一进度记录为依据。用户应收到与实际结果一致的完整固定报告；整个任务结束时完成适用的临时进度文件清理。
