本 Skill 使用执行清单组织归档流程。
各步骤的具体要求与完成条件以清单引用的执行说明为准。

# 输入

根据本次已完成的实现成果开展代码交付与归档。所需任务信息和成果位置按下列输入要求取得。

从已有上下文中取得：

- 目标项目的绝对路径。
- 集成 Worktree 的绝对路径。
- 集成分支和目标分支。目标分支默认使用 `main`；用户明确指定其他分支时，使用指定分支。
- 待归档实现提交。
- 本次已有结果产物的名称及实际路径或链接。
- 执行清单的实际绝对路径。已有清单时复用其位置；新建时采用用户指定的路径或项目已有明确约定的本地保存位置。无法确定时，向用户确认保存路径。

信息明确时直接使用；缺少生成清单所需的信息时，只针对无法从上下文确定的缺项向用户询问。

# 本地文本写入

遵守目标项目的文件写入约定，优先使用宿主文件编辑工具。使用 Python 写入文本时，在源码前两行声明 `# coding: utf-8`，文件读写显式指定 `encoding="utf-8"`。长文正文使用多行文本或独立数据输入，避免嵌成超长单行源码。交给新对话或子 Agent 执行时，传递本节要求。

# 执行流程

## 1. 生成或复用执行清单

检查本次任务是否已有执行清单。已有时，读取并核对任务信息，保留已有状态和记录，根据实际执行状态接续。

没有清单时，使用 Python 3 调用[清单生成脚本](scripts/generate-checklist.py)。脚本路径使用当前已加载 Skill 中的实际绝对路径。

调用示例，替换为本次任务的实际参数值：

```sh
python3 '/Skill绝对路径/scripts/generate-checklist.py' \
  --project '/项目绝对路径' \
  --worktree '/集成Worktree绝对路径' \
  --branch 'codex/example' \
  --target-branch 'main' \
  --implementation-commit '6f3a8b1' \
  --artifacts '[{"name":"Spec","location":"/集成Worktree绝对路径/docs/task/spec.md"},{"name":"Tickets","location":"/集成Worktree绝对路径/docs/task/tickets.md"}]' \
  --output '/集成Worktree绝对路径/docs/task/closure-checklist.md'
```

| 参数 | 内容 |
| --- | --- |
| `--project` | 目标项目的实际绝对路径。 |
| `--worktree` | 本次集成 Worktree 的实际绝对路径。 |
| `--branch` | 本次实现成果所在的集成分支。 |
| `--target-branch` | 本次交付的目标分支，默认 `main`；用户明确指定其他目标分支时传入指定值。 |
| `--implementation-commit` | 待归档实现提交号，接受 7 至 64 位十六进制文本。 |
| `--artifacts` | 本次实际已有结果产物的非空 JSON 数组。每项仅包含 `name` 和 `location`，分别填写产物名称及实际绝对文件路径或 HTTP(S) 链接，两者均为非空单行文本。 |
| `--output` | 执行清单的实际绝对路径。所在目录须已存在；已有文件会保留。 |

脚本会将 Markdown 清单写入 `--output` 指定的文件，并在标准输出中报告生成位置。

生成后，读取实际文件，核对任务信息、已有产物和执行说明引用，随后按照清单执行。

脚本执行失败时，报告具体错误，核对目标文件的实际状态。已有清单保留并读取核对；生成问题解决后再继续。

## 2. 按清单执行

遵循清单中的执行与记录规则，按表格顺序逐步推进。

涉及远程 Git、PR、Issue 等外部操作时，核对操作对象、范围和已有授权。已有授权覆盖本次操作时直接执行；缺少授权时，说明具体操作及影响，取得用户同意后执行。

执行当前步骤前，读取该行指定的说明文件及章节，按其中规定的顺序、操作要求、适用条件和完成条件执行。

按清单规则更新状态与简短记录，发生阻塞时向用户报告具体问题及接续所需信息。

清理工作区前，读取剩余步骤的执行说明。清单随工作区清理后，依据已读取的步骤和已有执行记录继续，在当前对话中简短记录后续结果。

执行说明缺失或尚未明确时，报告具体缺口，暂停受影响步骤，待明确后继续。

# 结果与完成条件

所有适用步骤均已完成，不适用步骤已有跳过依据，且没有影响本次归档的未解决事项时，本阶段完成。

完成判断以实际产物、Git 状态、必要的外部状态和执行记录为依据。按清单中的结果报告步骤向用户报告实际结果。
