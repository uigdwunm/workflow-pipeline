# 4归档

Stage 4 never implements code or republishes the implementation branch. It
accepts one exact `INTEGRATED` result and reads
[references/closure-actions.md](references/closure-actions.md) and
[references/closure-protocol.md](references/closure-protocol.md) before acting.

## Enter

Require the source checkpoint, implementation ID, worktree, branch, active
claim, accepted candidate, merge commit, verification, review and immutable
outcome proposal receipts from Stage 3. Do not accept a selector or a primary
checkout implementation path.

## Converge documents

Acquire `stage: change-closure`, `purpose: document-write` for exact paths and
the final remaining dependent implementation. Load every retained outcome
proposal for those paths. Apply/no-op/conflict uses exact before/after bytes and
never overwrites external edits. Commit only those paths under the short
publication slot and expected target HEAD.

New requirements are not closure proposals. Create a successor document, or
stop every dependent implementation and restart from a new checkpoint.

## Clean

Create a worktree closure checkpoint only after the publication is
`INTEGRATED` and document convergence is committed. Advance only through:

```text
documents-committed -> worktree-removed -> branch-removed
-> execution-claim-released -> archived
```

The checkpoint performs and verifies each side effect. It removes only the
exact clean registered worktree and proven-integrated branch without force.
It releases source protection and then the claim; the claim is last. Persisted
intent allows uniquely proven absence/release to be adopted after a crash.
Unexplained absence or changed identity blocks.

After `archived`, record archive completion in the discussion lifecycle and
conditionally close the topic. Other active dependencies or unresolved
relations keep it open. Report exact document commit, cleanup receipts, claim
release and retained closure checkpoint. This is the final stage.

On success, end with:

```text
归档结果：成功
变更生命周期：已归档；话题=<closed | retained with reason>
归档提交：<documentation commit | none>
清理结果：worktree、branch、source protection、execution claim 已按 checkpoint 验证
远程操作：<performed actions | none>
```
