# Closure Actions

Read only the section needed for the current closure action. The retained state
machine and immutable evidence rules remain authoritative in
`closure-protocol.md`.

## Repository and lease gate

Normalize `git status --porcelain=v1 -z --untracked-files=all`, excluding only
verified managed Skill links. Require clean implementation paths and index;
preserve recognized documentation and stop on unknown work.

Verify the stage-3 mode, source, commits, merge ancestry, workspace, exact
handoff and supervision evidence. For new runs require the matching zero- or
isolated-worktree facts; legacy runs keep their embedded protocol without
migration. Acquire the exact mode's short closure authority before Git
mutation, then revalidate all facts.

Before documentation writes read the shared document-lease protocol and acquire
`stage: change-closure`, `purpose: document-write`. Verify before writing,
release after the bounded commit or no-op, and never hold it while waiting.

Held authority queues through the stable lease-wait footer. Unknown user work
uses the stable workspace-assistance footer. Generic approval permits only
inspection and a proposal; destructive actions require exact separate
authorization.

## Reconcile and commit documents

Update existing documents in place. Reconcile only established Spec/Tickets
and source-topic documents against accepted evidence. Preserve format and
wording; check criteria only when proved. Do not invent replacement planning,
release notes or changelogs.

Show the exact local closure plan before mutation: document changes, mode,
base, branch/worktree, commits, paths to stage, commit message, non-force cleanup,
lease release, retained checkpoint, verification and requested remote actions.

At the prepared checkpoint, stage only exact closure-owned document pathspecs,
verify the entire diff and commit concisely. Never stage implementation or
another task's documentation, never use broad add commands, and never create an
empty commit. Release the document lease after verified commit/no-op.

## Clean, deliver and release evidence

Follow the exact mode branch in `closure-protocol.md`. Use only non-force
worktree/branch cleanup, release the exact execution/repository lease, and
advance after each verified receipt. Missing or ambiguous effects remain
recoverable and are never repeated blindly.

Perform only separately authorized remote operations. Then inspect and advance
immutable stage-3 evidence cleanup one atomic step at a time. Retain the
complete closure checkpoint and remove no unexpected sibling.

The stable local rules include: `Do not implement code`; `stage only exact
closure-owned document pathspecs`; unknown work is preserved; and remote writes
remain separately authorized.
