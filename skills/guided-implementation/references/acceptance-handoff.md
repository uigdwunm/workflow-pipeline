# 验收结果登记与接续

所选分支完成第 3 步的验收整改后，由主对话按本说明统一登记结果，交给第 4 步继续处理。

## 整理交接信息

核对集成 Worktree 属于原目标项目，当前分支和已验收实现提交与实际成果一致。整理已有成果的实际路径或链接，以及所选分支确认的验收、审查整改和停止写入结果；记录用户常用工作区及其当前检出状态。

检查未提交内容时区分其归属，不将临时进度文件作为实现交付内容。已确认的成果和验证结论直接复用，恢复时仅核对缺失或发生变化的信息。

存在既有测试失败时，一并交接归属依据、适用基线及条件、验证限制，沿用现有记录。仍阻断必要验收的，按入口[测试失败归属与收敛](../SKILL.md#测试失败归属与收敛)保持第 3 步未完成。

## 登记与接续

用 `complete --stage 3 --steps '[{"step": 3, "note": "本步骤的实际完成结果"}]'` 记录集成 Worktree、集成分支、已验收实现提交、已有成果位置、验收与审查整改结论、已停止写入的核对结果及常用工作区状态，传入入口[任务进度](../SKILL.md#任务进度)中的同一进度身份，结果填入列表项的 `note`。整改和复查过程不单独写入进度。

保留集成 Worktree 和分支，读取并执行第 4 步[分支检查与文档收尾](delivery-preparation.md)，在确定交付目标和方式后保存归档输入。
