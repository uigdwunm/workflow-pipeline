# 子 Agent 模型与强度

本规则适用于探索、实现、合并和审查子 Agent。每次创建前，按以下规则确定并应用设置。

用户或其他适用提示词已规定模型、推理强度或选择规则时，按相应要求执行。以下默认规则仅补充未被约定的部分。

通过当前宿主已有的工具说明、查询能力、配置或会话信息，获取当前对话设置、用户默认设置，以及可用于子 Agent 的模型和各模型支持的推理强度。

默认以当前对话模型和用户默认模型中较贵的那个作为价格上限，根据任务需要选择不超过该上限的可用模型。模型能力和模型下限不作限制。

比较价格时，优先使用已有知识，不为此专门联网查询。

创建前，根据本次交给子 Agent 的实际任务，分别确定模型和推理强度。不能仅因主对话正在使用某套配置，就直接将其作为本次选择。

在既定价格上限内，按以下方向选择：

- **范围明确、可按既定步骤完成**：如查引用、核对清单、无冲突合并，优先选择能够胜任的低成本模型，推理强度通常选择 `low` 或 `medium`。
- **需要理解逻辑、处理边界或作出局部判断**：如常规实现、行为测试、代码审查，选择适合代码理解和工具执行的主力模型，推理强度通常选择 `high`。
- **需要解决重要歧义或复杂取舍**：如架构设计、跨模块耦合、数据一致性及复杂故障定位，选择价格上限内适合该任务的较强模型，推理强度通常选择 `xhigh` 或其他受支持的相应档位。

上述分类以实际任务为准，不能只按“探索、实现、合并、审查”的角色名称判断。任务具备跨类特征时，根据影响结果的主要难点选择。

用户默认模型无法获取，或无法可靠比较价格或能力时，沿用当前模型，并简要记录原因；推理强度仍根据本次任务独立选择，不受当前对话或用户默认强度限制。所选强度必须是该模型支持的档位。

在现有进度记录或创建前说明中，简要记录：任务难点、所选模型与强度、选择依据，以及是否使用继承。任务特征和配置相同的一批子 Agent，可以合并说明。

先确定所需模型和强度，再选择能够应用这些设置的创建方式。

宿主允许显式设置时，将所选模型和强度传入创建工具。完整历史继承模式不支持覆盖设置时，任务能够完整交接的，使用独立上下文创建，并传入必要背景、约束和资料。

任务确实依赖完整历史时，可以保留继承方式，但应说明该依赖，并确认继承配置能够满足任务需要。

创建后，由创建者通过工具回执或可查询的会话设置，核实所创建子 Agent 的实际模型与推理强度；仅发出了创建请求，不视为已经应用成功。被创建者无需重复核实自身设置；它继续创建下级子 Agent 时，承担相同的创建者责任。

无法确定可用设置、无法确认继承符合要求，或宿主无法应用要求的设置时，按 [SKILL.md 中“意外中断”的处理要求](../SKILL.md#意外中断)向主对话报告，由主对话处理。
