# 清理资源

本说明用于第 7 步。第 6 步完成后读取，执行时遵守入口的[全程规则](../SKILL.md#全程规则)。

## 处理 Worktree

依据当前任务的创建或复用记录、Git Worktree 登记信息，
以及可查询的宿主信息，核对归档输入中工作区的实际位置和处理方式。

按来源处理：

- Codex 托管 Worktree 的归档和移除由宿主管理。
- 本流程自行创建的普通 Git 临时 Worktree：
  完成交付并通过本节的清理前核对后清理。
- 复用的长期或共享 Worktree：
  保留。

已有信息不足以确定来源、归属或清理范围时，
保留工作区，记录已知情况和具体缺口。
需要用户决定时，只针对该工作区的具体问题确认。

### 清理前核对

对本流程创建的普通 Git 临时 Worktree，核对实际内容和使用情况：

- 根据已有任务要求和实际 Git 状态，
  需要交付或已明确要求保留的内容均已处理。
- 当前任务的相关实现和整改写入已结束，
  现有任务记录及可查询信息中没有显示其他任务仍在使用该工作区。

检查工作区内容时，区分本次辅助资料与需要交付、保留的内容。
统一进度文件位于临时 Worktree 之外，清理工作区时继续保留。

发现未交付的实现修改、归属不明确的文件，
或已知仍需使用工作区的任务时，保留工作区并记录具体原因。

条件满足后，按已确认的可清理范围使用 Git Worktree 清理机制，
移除对应工作区，核实实际结果。

保留工作区时，记录实际路径和保留原因。

## 清理任务分支

根据进度文件和已有任务记录，
核对并清理本次任务交付后不再需要的集成分支及临时开发分支，
包括子 Agent 创建的分支。
Worktree 是否由 Codex 托管不改变本次任务分支的清理责任。

保留目标分支、历史保留分支、长期或共享分支，
以及用户明确要求保留的分支。

删除前核对：

- 分支属于本次任务，名称和当前提交已确认。
- 分支中的交付内容已进入指定目标分支，
  没有尚未交付的新修改。
- 该分支不再用于本次后续工作，
  已有记录中没有其他任务仍需使用它。

合并方式导致提交号变化时，
结合实际合并记录和内容差异核实交付结果，
不能仅凭提交号不同判断成果尚未交付。

### 处理 Worktree 占用

分支仍被其他任务或长期、共享工作区使用时，
保留分支并记录原因。

本次专用但保留的 Worktree 仍检出待清理任务分支时，
完成上述归属、交付和使用情况核对后，
按宿主允许的方式解除分支占用，保持当前提交及需保留的文件状态，再清理分支。
该操作仅限本次专用任务 Worktree，常用工作区仍遵守入口的用户工作区保护要求。
无需用户再次单独要求删除本次已交付且不再使用的临时分支。
无法安全解除占用时，保留资源并报告具体阻塞，分支清理保持未完成。

### 执行清理

对满足条件的本地分支执行删除，并核实结果。
不能通过强制删除绕过归属和交付内容的核对。

本次明确要求清理远程分支时，
核对远程仓库和分支，再执行并核实。
分支已经不存在时，核实并记录即可。

应清理但尚未完成的 Worktree 或分支，
保持未完成，继续处理或报告具体阻塞。

## 完成条件

- Worktree 已按来源及用途处理；本次任务不再需要的集成分支及临时开发分支已清理，需保留的资源已记录路径、用途及依据。
- 资源操作结果已核实，没有应清理但尚未完成的事项；有阻塞时保留接续资源并保持步骤未完成。

## 进度记录与接续

完成条件满足后，用 `complete --stage 3 --steps '[{"step": 7, "note": "本步骤的实际完成结果"}]'` 记录已清理、保留及不由本 Skill 管理的资源，包含必要的路径、分支名称和原因，传入同一进度身份，结果填入列表项的 `note`。同一任务进度文件继续保留，返回入口执行第 8 步[最终报告](../SKILL.md#8-最终报告)。未受后续变化影响的交付、状态和资源结论直接复用，无需重复查询。
