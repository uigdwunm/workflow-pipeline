# 分支检查与文档收尾

本说明用于第 4 步。第 3 步完成后读取，执行时遵守入口的[全程规则](../SKILL.md#全程规则)。

## 确定交付方式与合并策略

根据用户要求、项目约定和已有授权，确定并记录本次交付方式、
实际仓库、目标分支及合并策略。目标分支优先采用用户明确指定的分支，其次采用项目约定；均未指定时默认 `main`。保存归档输入前核实该目标适用于本次交付。

- 本地交付：以本地目标分支为交付依据。
- 直接推送：以指定远程仓库的目标分支为交付依据，核对本地与远程差异。
- PR 合并：以 PR 的实际目标仓库和分支为交付依据，
  核对其与本次要求一致，按仓库规则完成交付，无需预先合入本地目标分支。

沿用项目规定的 merge、squash、rebase 或平台合并策略，
同时明确适用的分支保护和必需检查。
已有要求明确时直接使用；无法确定且会影响交付对象或历史处理方式时，
说明具体选择及影响，向用户确认。
本步骤确定操作路径，实际操作仍遵守入口的授权要求。

本地交付还须核对用户常用工作区的实际路径和检出分支。
该目录检出目标分支时，确定以该目录的目标分支为本地交付位置。
第 5 步在任务 Worktree 中完成整合、冲突处理和必要验证后，
再将已验证成果合入该目录的目标分支并更新实际文件，保持其检出分支不变。
用户自行检出其他分支时保持其选择，
以不改变该目录检出的方式更新同一目标分支，并报告两者的实际状态。
无法核实分支变化的归属、发现其他任务占用或无法安全交付时，
报告具体阻塞，不通过切换用户分支或接管其他任务工作区绕过。

## 保存归档输入

交付方式、实际仓库、目标分支及合并策略明确后，结合第 3 步记录的已验收实现提交、集成 Worktree、集成分支和已有成果位置，用同一进度脚本的 `enter --stage 3 --closure ...` 保存归档输入。该命令复用当前轮次，不重置开始时间。首次保存须在第 3 步完成后、第 4 步完成前，传入同一组 `--file`、`--task-id`、`--project`。将以下示例替换为实际值，作为 `--closure` 的 JSON 参数：

```json
{
  "worktree": "/集成Worktree绝对路径",
  "branch": "codex/example",
  "target_branch": "main",
  "implementation_commit": "6f3a8b1",
  "artifacts": [
    {"name": "已有成果", "location": "/实际成果绝对路径"}
  ]
}
```

这份输入保留已验收成果的基准，后续文档、整合及实际交付提交记入对应步骤结果，不改写原输入。已保存且内容相同的输入可以重试，内容不一致时先核实，不能覆盖。恢复时，结合当前步骤记录识别本流程产生的后续提交，不因 HEAD 已改变而否定原验收基准。

登记失败时保留已完成的第 3 步及已有成果，核实后补齐输入，再继续本步骤的分支检查与文档收尾；不重新运行已经通过的实现验收。恢复时若输入已保存，核对并复用原记录，不重新登记。

## 检查目标分支变化

本地交付时读取本地目标分支；远程交付时，先刷新指定远程的对应引用，
核实实际远程目标提交，不能用未刷新的引用或本地同名分支代替。
本地与远程不一致时，查明差异及归属，按已确定的交付方式处理；
本地独有提交不能因分支同名而混入远程交付。

记录本次检查所依据的目标提交。
结合本次实现与目标分支的共同基线，
检查目标分支新增的提交和文件改动。

重点判断：

- 新增修改是否影响本次实现涉及的功能、接口、共享逻辑或依赖。
- 相关文档是否发生变化，本次文档调整是否需要据此修正。
- 已有验证和审查结论是否仍然适用，
  哪些范围需要在代码整合后重新检查。

将目标分支提交、变化影响，
以及合并时需要处理的事项记入简短记录。

检查结果涉及已确认目标、范围或设计的变化时，
说明具体问题和影响，取得用户决定后继续。

## 完成文档收尾

根据已确认要求、本次实现、目标分支变化及项目文档约定，
确定需要调整的 README、使用说明、配置说明、
技术文档或 CHANGELOG。

能够明确的文档调整，以及项目允许在合并前更新的仓库内任务状态，
在集成 Worktree 中一并完成，
沿用已有格式，核对涉及的路径、链接、配置和调用示例，
将需要交付的修改提交到集成分支。

文档调整依赖尚未确定的合并方案时，
记录具体事项，
在第 5 步[整合与交付](delivery.md)中完成。
必须以合并成功为前提的状态留到第 6 步更新，
遵守项目对实现完成与合并完成的定义。

无需调整文档时，记录判断依据。

将文档调整结果、提交号及待处理事项记入简短记录。

## 完成条件

- 归档输入已保存到同一进度文件，与已验收成果及本次确定的交付目标一致。
- 交付方式、实际仓库、目标分支、合并策略和适用检查已明确；本地交付的常用工作区路径及检出分支已核实。
- 目标提交、变化影响及需要重新检查的范围已核实并记录。
- 当前能够明确的文档调整已完成必要检查并提交；
  无需调整时，判断依据已记录。
- 合并时待处理的代码和文档事项已明确。

## 进度记录与接续

完成条件满足后，用 `complete --stage 3 --steps '[{"step": 4, "note": "本步骤的实际完成结果"}]'` 记录交付方式、实际仓库与目标分支、合并策略、目标提交、变化影响及文档结果。本地交付还须包含常用工作区路径及检出分支。传入同一进度身份，结果填入列表项的 `note`，再读取并执行第 5 步[整合与交付](delivery.md)。
